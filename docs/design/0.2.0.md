# 0.2.0 implementation contract

Status: in development. Keep existing `print` and `serve` commands and 0.1.x JSON
logs compatible. Core dependencies remain empty. API lifecycle instrumentation
is a prototype candidate, not a release requirement.

## Shared records

New JSON log records retain their existing fields and add a `schema_version: 1`,
`event_id`, `run_id`, and `kind` envelope. IDs are opaque strings. Call and parent
IDs remain in `data` for old viewers. A process gets an implicit run identity;
explicit `Run` scopes provide start/end/error events. Unclosed runs are incomplete,
not proof a process is alive. Forked processes must not reuse implicit run IDs.
Legacy records have a synthetic file-scoped run and preserve original call IDs.
Unknown schema versions must fail clearly in the new CLI.

## CLI contract

New commands: `runs`, `tree`, `call`, `path`, `errors`, and `payload`. JSON is the
default; successful responses contain schema_version, command, data, source,
warnings, and next_cursor. Errors are JSON on stderr with an error code and message;
exit 1 means an operational/data failure, exit 2 invalid arguments. Existing
commands retain their previous defaults and response shapes.

List commands default to 100 results, at most 1,000. Cursors bind to file content
and query; modifying the log invalidates them. Reads and serialized output have
explicit size limits. Call summaries omit captured content; payload retrieval is
explicit and byte-bounded. Do not silently follow file paths from log records.
Cycles and missing parents must terminate safely and remain visible.

## LLM workflow

Confirmed scope: OpenAI Chat Completions/Responses, Anthropic Messages, and
LangChain. Content capture defaults on for local development, with explicit
disabling, byte limits, and redaction. Both sync/async behavior and streaming completion/cancellation require
coverage. Tool-call IDs should be recorded for linking, without pretending tool
execution was automatically instrumented.

## Release gates

- Existing regression suite and Python 3.9–3.13 support.
- Legacy/new log compatibility and adversarial CLI records/cursors.
- Scripted failure investigation and equivalent viewer inspection.
- One tested optional LLM adapter, including streaming, errors, and cleanup.
- No live credentials required for deterministic integration tests.
- Build, docs, lint, bounded-capture checks, and measured local overhead.

## Development validation — 15 September 2026

The first implementation milestone is local on `codex/0.2.0`, version
`0.2.0.dev0`; no release or publication has been performed.

- Python 3.9, 3.10, 3.11 and 3.13: 232 tests passed per interpreter, with the
  optional SDK module skipped. Final Python 3.12 run with the SDKs: 248 tests passed.
  A subsequent capture-truncation regression passed, and the final Python 3.11
  coverage run passed 233 tests (one optional module skipped), at 70% coverage.
- Real SDK objects were tested with synthetic HTTP/SSE transports for all three
  provider formats: sync/async responses, async stream completion, sync early
  close, and LangChain callbacks. No live provider requests or credentials.
- Additional regressions cover stream fragments containing split credentials,
  Responses failure/incomplete events, tool IDs in metadata-only mode, callback
  parent relationships across threads, FIFO input rejection, bounded cursors,
  viewer Host/Origin checks, CSP headers, and HTML escaping in the flame graph.
- A synthetic failing run produces matching parent/call IDs and outcomes in
  CLI inspection and the viewer. A real browser displayed LLM content and usage
  under the CSP without console errors; HTML-looking output remained text.
- The final wheel passed the repository's standalone runtime and viewer smoke
  programs: normal/error/interrupt shutdown each flushed 80 unique records;
  async application tracing, installed CLI analysis, viewer HTTP APIs, log
  replacement, and stale-payload rejection passed. The sample recursive class
  application also produced the expected five-call hierarchy and metrics.
- `scripts/smoke_llm_agent.py` passed against the installed wheel with real
  OpenAI/Anthropic/LangChain types and in-memory provider transports. It checked
  Chat Completions, Responses, Messages, LangChain, stream redaction, propagated
  provider failure, all agent investigation steps, and viewer/CLI agreement.
- The final wheel exported four spans to a real local Collector, including the
  expected async parent/child relationship, exception event and error status,
  service name, and normal-shutdown flush. No external exporter was configured.
- Ruff, whitespace checks, strict MkDocs build, and sdist/wheel builds passed.
  The wheel is approximately 101 KiB (424 KiB unpacked), with no required runtime
  dependencies. Optional SDK baseline packages require Python 3.10+.
- `pip-audit` checked 77 published packages in the isolated Python 3.12 SDK/OTEL
  environment and reported no known advisories. It could not audit the unpublished
  PyEzTrace version itself. This is a dated dependency check, not a security
  certification or a claim covering every possible optional-extra resolution.
- A local synthetic microbenchmark (five batches of 200 calls per mode, 500-character
  input/output, unbuffered JSON file and console logging) measured median elapsed
  time of about 564 µs/call in metadata-only mode and 631 µs/call with content.
  These include two log writes and capture work, omit network/provider latency,
  and are indicative local measurements rather than performance guarantees.

Before release: complete review and hosted Linux CI, including the configured
Python 3.10/3.13 optional SDK jobs; review the public adapter/CLI contracts and
capture defaults; approve a release candidate and publication. The initial SDK
surface is explicit `create`/`create(stream=True)` wrappers, not convenience
stream/parse/batch helpers. The viewer still lists top-level calls as trace runs;
full application-session navigation and process liveness remain future work.
